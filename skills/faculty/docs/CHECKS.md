# Checks and known limitations

Faculty has been checked for instruction consistency, saved artifacts, role boundaries and representative course workflows. These results describe the conditions exercised; they do not establish reliability percentages or measured learning outcomes.

## Existing coverage

The results in this section were added in commit `9e89e34` on 2026-10-03. That is a documentation commit, not a record of what was tested: the tested revision, host and model, check definitions and raw results are not in the repository. Since then, 17 files across the seven skill directories have changed (as of `becbbf2`). These historical totals do not validate later changes. A future run should record the tested revision, host and model, settings, fixtures, expected and observed outcomes, and where its evidence is retained.

The final instruction and format review reported 88 passing checks, including 47 resolving instruction links. Shared course-state coverage exercised all four roles that write routing state, with 8 cases, 72 mechanical/runtime/preservation checks and 32 manual criteria passing after a correction.

Focused follow-ups covered these paths:

| Workflow | Mechanical/runtime/preservation checks | Manual criteria |
|---|---:|---:|
| Advisor research correction and acceptance | 19/19 | 5/5 |
| Editor using replacement-unit evidence | 16/16 | 5/5 |
| Editor reviewing a live event-handling defect | 20/20 | 5/5 |
| Editor → Teacher → Tutor → Editor with persistent memory disabled | 45/45 | 6/6 |

The last workflow used fresh sessions and synthetic learner replies. It exercised the handoffs without measuring a real person's understanding or retention. A separate controlled routing correction demonstrated recovery after an introduced faulty write; it does not establish autonomous recovery in every session.

## Earlier problems and corrections

- **Routing state:** Earlier sessions recorded stale timestamps or included instructional detail in the routing record. Shared rules now require fresh tool-observed UTC, workflow-only content and read-back of the saved record. Focused follow-ups passed; the earlier failures remain part of the validation history.
- **Analogy fidelity:** Roommate initially failed one of five conversations. A targeted follow-up passed four conversations after its analogy-checking instruction was clarified. This supports the exercised examples, not universal analogy correctness or proof that the wording caused the improvement.
- **Unexpected prior context:** Earlier Roommate use with ordinary memory exposed unwanted history. Some memory-off coverage used independent replacement conversations, and a representative course workflow also passed with memory disabled. Neither establishes universal isolation across hosts.
- **Research correction:** One Advisor session directly changed a research entry. A follow-up used a dedicated research worker to append a correction while preserving the original. Final acceptance followed completed research, but some preliminary draft writes occurred earlier.
- **Validation-tool compatibility:** A generic validator accepted Librarian but rejected six required manual-invocation skills because it did not recognize `disable-model-invocation`. Removing the field from disposable copies isolated that incompatibility. The maintained policy remains; those original validator results are not relabeled as passes.
- **Browser and procedure limits:** Editor reproduced an event-handling defect and rejected the artifact. Programmatic events and Tab traversal do not establish physical typing, native dropdown behavior, screen-reader usability or visual quality. Other sessions encountered browser/snapshot problems, and an earlier terminal-status procedure failed. One Teacher handoff disclosed saved notes as unrendered after browser access was denied. Later rendering cannot establish that inspection occurred before publication.

## Evidence and fresh-session scenarios (2026-11-10)

Three rounds of scenario runs tested the changes that added Tutor evidence excerpts, Editor aid disclosure, fixed released criteria and the fresh-session check. Each run used Codex CLI 0.167.0 with model `gpt-6.1-sol` in headless multi-turn sessions. Each role ran as a separate process in a fresh copy of a synthetic course folder, with synthetic learner replies. Round 1 tested commit `7edc009c` at low reasoning effort, with fixed learner scripts and a baseline run of `becbbf2` for the fresh-session case. Rounds 2 and 3 tested `6037fb2c` and the last tested wording `f0128358` at high effort, with each learner reply generated by a separate process from a static policy. `7edc009c` and `6037fb2c` were local drafts and are not in the published history; `f0128358` is.

| Scenario | Expected | Round 1 (13 runs) | Rounds 2 (15 runs) and 3 (6 runs) |
|---|---|---|---|
| Tutor evidence excerpts | Prompts and responses copied exactly | Different: every prompt was flattened to one line in a table cell, with fenced code turned into inline code, and a multi-line answer was split into fragments joined by narration | As expected, including a multi-line answer with code, a response that was not counted, and `No exchange occurred` for an unreached criterion |
| Tutor reevaluation | New prompts, linked attempt, prior report unchanged | As expected after improvised learner answers; the fixed-script retry ended unfinished because the script did not answer the prompts asked | As expected, with no prompt reused |
| Editor aid disclosure | Wait for the answer and record it in the review | Different: saved an approval as `Not disclosed` before the answer, then wrote disclosure files no format defines | As expected for documentation only, `Permitted Aids: None`, a formatter and linter, and a declined answer |
| Disclosed help outside the permitted aids | Affected criterion `NOT MET`, `REJECTED`, learner revision | Different: no rule existed; Editor set the course to Blocked for Advisor on a rule it invented | As expected, then approved after an independent rewrite |
| Changed criteria or aids on resubmission | Blocked to Advisor without a recovery trail; ordinary review otherwise | As expected for the blocker, which also wrote an undefined recovery note, and for an unchanged task | As expected with no trail, a ledger trail only, a Teacher record only, an unchanged task and a baseline-format prior review |
| Fresh-session check | Decline after an assistant taught or helped in the conversation | As expected; baseline Tutor began assessing straight after teaching | As expected, and no decline for notes the learner pasted |
| Editor clarification and legacy Tutor report | No new review; legacy report accepted unchanged | Clarification as expected; legacy report preserved, but the fixed-script attempt ended unfinished and a supplemental attempt with improvised answers produced the new report | Not rerun |

The round 1 differences led to the block-style excerpts, the wait for the aid answer and the rule for disclosed help outside the permitted aids. Harness faults in rounds 1 and 2, such as read-only resumed sessions and scripted answers that missed the prompt asked, were corrected or rerun and are recorded in the round reports.

Each run is a single synthetic observation on one host and model; none ran in Claude Code. Teacher and Advisor were not run, so remediation records, the Advisor correction trail and prior reviews were hand-built. The changed-task cases changed criteria and Permitted Aids together, and Editor grounded its blocker in the aid change, so a change to criteria alone was not isolated. Gate-remediation lesson numbering, Teacher's side of the release rule and the [usage guide](USAGE.md) wording were not exercised. Changes made after the last run were reviewed but not run: the widened resubmission comparison and the later review fixes recording permitted aids and criterion wording in reviews, allowing learning records that concern no lesson, fencing multi-line or markup-bearing excerpts, and continuing a gate remediation already in progress. Round 1 and rounds 2 and 3 used different effort settings and are not directly comparable. The three round reports are attached to the pull request that adds this section; full transcripts and course snapshots are not retained with the repository or that pull request.

## Beta limitations

Long-term retention, transfer and real learner outcomes remain unmeasured. Delayed review records later evidence; it does not measure retention across learners.

Learner-requested withdrawal, challenge entry and delayed review were checked only by source walkthroughs of synthetic course states. No live agent session has exercised them. Teacher-commissioned research in real use and all combinations of practice, remediation, contract replacement and recovery are not exhaustively covered.

No installer compatibility result is claimed for the beta. Role discovery, saved-state loading, research-worker availability and HTML inspection depend on the app, account and available tools. Installing the skills does not establish those capabilities. Initialization's host preflight was revised from a source review and a synthetic walkthrough; it has not yet been exercised in a live session on any host.

Report unexpected behavior through [issues](https://github.com/lonlydwolf/skills/issues), with the affected skill, last installation or update, tool/version, expected result and a small redacted example.
